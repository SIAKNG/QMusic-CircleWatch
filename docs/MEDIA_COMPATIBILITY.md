# 系统媒体控制兼容性

2026-11-07 本地修订，应用版本维持 1.1。

应用通过 MediaLibraryService / MediaLibrarySession 提供标准 Android 媒体会话和媒体浏览连接，兼容旧版 MediaBrowserService 发现入口。浏览根目录仅用于建立连接，不对外公开账号歌单；上一首、下一首路由到应用现有队列与权限检查。会话提供返回应用的启动入口，并声明音乐应用类别。

原始 OPPO 控件说明 V7.0.18（80 页）及配套 AAR 未找到音乐应用注册或 Watch X3 选择列表接入说明。其列表、表冠和振动接口已作为现有适配依据。

当前 OWW251 原厂“请选择音乐应用”页面使用固定包名名单，并非自动枚举所有已安装音乐应用。本工程的默认独立包名不在该列表中。因此标准媒体会话可以被系统发现，不等于原厂选择页必然显示本应用。默认版保持独立包名，未修改系统程序。

本轮进一步检查了手表内实际“媒体控制”应用，而不只检查启动器选择页。该应用在枚举活动媒体会话、选择和注册回调时也先按固定包名映射过滤；其中包含原版 QQ 音乐手表版，未包含本应用独立包名。实机真实播放时系统可读到活动会话、歌曲元数据和推进中的播放位置，原厂界面仍显示“未在播放”。因此仅声明标准服务或增加权限不能解决这份原厂名单限制。

另定位到一个应用侧标准兼容问题：显式指定上一首/下一首按钮槽位后，当前 Media3 会把它们转换为旧会话自定义操作，同时移除标准 ACTION_SKIP_TO_PREVIOUS/NEXT 标志。已改用默认标准按钮配置，保留应用队列、权限校验与媒体键处理。旧式控制器不再需要识别应用自定义命令。转换行为依据 [Media3 1.10.1 源码](https://github.com/androidx/media/blob/1.10.1/libraries/session/src/main/java/androidx/media3/session/MediaSessionLegacyStub.java)。这项修正与原厂固定名单是两项独立限制，不能据此宣布原厂入口已兼容。

当前未连接 Watch X3（OWW261），不能宣布 X3 的原厂媒体选择页已修复。需要 X3 实机确认其入口机制，或由 OPPO 提供适用的官方接入流程。

自动测试覆盖服务声明、媒体浏览器连接与根目录、标准队列控制和命令可用性事件。真实设备原始日志与厂商二进制分析资料只保存在本地项目中，不随源码上传。

2026-11-07 最终 1.1 包在 OWW251 上通过独立平台 MediaController 实测：暂停为 STATE_PAUSED，恢复为 STATE_PLAYING，位置从 49.479 秒推进到 53.687 秒；标准 skipToNext/skipToPrevious 均切换真实歌曲元数据，最后暂停成功。播放时 actions=7340027、暂停时 actions=7340029，均包含标准前后切歌标志，且没有旧的自定义按钮替代项。完整 268 项自动回归通过，Lint 零错误、62 条既有警告。实机结果仅代表当前连接的 OWW251；原厂固定名单问题仍未解决。

用户随后明确要求按 QQ 音乐包名尝试接入，已增加显式选择的同工程兼容构建并安装，仍保留本项目签名与第三方身份。该包重新扫码后，OWW251 原厂界面的真实歌曲、封面和新图标，以及播放、暂停、上一首、下一首均已单独验证通过。其适用范围、官方版冲突与完整记录见 [固定名单兼容构建](OPPO_MEDIA_COMPAT.md)。默认独立版仍受原厂名单限制，X3 未实测。
